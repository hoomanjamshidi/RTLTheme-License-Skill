# RTLTheme License Skill

**اسکیل Claude Code برای لایسنس‌گذاری راست‌چین روی هر افزونهٔ وردپرس**

این اسکیل کل فرایند آماده‌سازی یک افزونهٔ وردپرس برای فروش در [راست‌چین](https://www.rtl-theme.com) را به Claude Code یاد می‌دهد:

- اجباری کردن نصب و فعال بودن «افزونه مدیریت هوشمند راست‌چین» (RTL-CareUnit)
- قرار دادن و بررسی فایل لایسنس `RTL_License_*.php`
- قفل کامل افزونه بدون لایسنس
- افزودن زیرمنوی «مدیریت لایسنس»
- ساخت بستهٔ نهایی برای ارسال به بازبینی

این اسکیل از تجربهٔ واقعی ساخته شده است: افزونهٔ «سوالیتو» دو بار در بازبینی راست‌چین رد شد. هر قاعدهٔ این اسکیل جواب یکی از همان ایرادهاست.

## این اسکیل چه کار می‌کند

قاعدهٔ اصلی بازبینی راست‌چین این است:

> **بدون افزونهٔ «مدیریت هوشمند راست‌چین» و بدون لایسنس فعال، محصول نباید هیچ قابلیتی ارائه کند.**

اسکیل در این کارها به Claude کمک می‌کند:

| کار | نتیجه |
|---|---|
| پیدا کردن همهٔ نقاط ثبت قابلیت افزونه | هیچ هوکی بیرون از گیت جا نمی‌ماند |
| ساخت `<prefix>-bootstrap.php` از قالب | گیت کامل با ترتیب درست بررسی‌ها |
| انتقال راه‌اندازی هستهٔ افزونه به پشت گیت | افزونه بدون لایسنس کاملاً بی‌اثر است |
| حالت قفل استاندارد | اعلان مصوب، لینک فعال‌سازی، شورت‌کدهای ساکت |
| زیرمنوی «مدیریت لایسنس» | فقط با لایسنس فعال و زیر منوی خود افزونه |
| ممیزی خودکار | ساختار، هوک‌های خارج از گیت و بوت واقعی در حالت قفل |
| بسته‌بندی | بستهٔ تمیز با فایل لایسنس دست‌نخورده و هدر سالم |

## پیش‌نیازها

- [Claude Code](https://claude.com/claude-code)
- PHP 8.0 یا بالاتر در خط فرمان (برای اسکریپت‌ها)
- `zip` (برای ساخت فایل بسته)
- **فایل `RTL_License_<hash>.php` مخصوص همان محصول**، دریافت‌شده از پنل فروشندهٔ راست‌چین

> ⚠️ **فایل لایسنس برای هر محصول متفاوت است.** باید جداگانه برای همان محصول از راست‌چین دریافت شود و در **ریشهٔ پوشهٔ افزونه** قرار بگیرد. هرگز آن را از افزونهٔ دیگری کپی نکنید و محتوایش را تغییر ندهید. فایل با ionCube انکد شده است و sha1 آن بررسی می‌شود؛ یک بایت تغییر یعنی افزونه برای همیشه قفل می‌ماند.

۲. Claude Code را در پوشهٔ افزونه باز کنید و بنویسید:

</div>


<div dir="rtl">

یا به زبان خودتان، مثلاً: «برای این افزونه لایسنس‌گذاری راست‌چین انجام بده».

Claude این گام‌ها را انجام می‌دهد: شناخت افزونه، ساخت bootstrap، انتقال هسته به پشت گیت، ممیزی، بسته‌بندی. در پایان چک‌لیست ارسال را با شما مرور می‌کند.

## روند کار، گام‌به‌گام

### گام ۰: فایل لایسنس

- وجود دقیقاً یک `RTL_License_*.php` در ریشهٔ افزونه بررسی می‌شود. اگر نباشد، کار متوقف می‌شود و از شما خواسته می‌شود آن را از راست‌چین بگیرید.
- «Product Link» داخل سرآیند فایل نمایش داده می‌شود تا تأیید کنید فایل مال همین محصول است.

### گام ۱: شناخت افزونه

- **فایل اصلی** (دارای هدر `Plugin Name:`) پیدا می‌شود. نام آن و نام پوشه **تغییر نمی‌کند**.
- پیشوند توابع، text domain، نام فارسی محصول و اسلاگ منوی اصلی پیشخوان مشخص می‌شود.
- همهٔ `add_action`، `add_filter`، `add_shortcode`، `register_*` و `get_instance` پیدا می‌شوند.
- همهٔ تگ‌های شورت‌کد، از جمله تگ‌های قدیمی، فهرست می‌شوند.

### گام ۲: ساخت bootstrap

</div>

```bash
php ~/.claude/skills/rtl-license/scripts/scaffold.php \
    --plugin-dir=/path/to/plugin --prefix=myplug \
    --product="نام فارسی محصول" --textdomain=myplug \
    --menu-parent=myplug-settings --shortcodes=myplug,myplug_list
```

<div dir="rtl">

سپس در فایل اصلی:

</div>

```php
if (!defined('ABSPATH')) exit;

if (!defined('MYPLUG_MAIN_FILE')) define('MYPLUG_MAIN_FILE', __FILE__);
define('MYPLUG_PLUGIN_PATH', plugin_dir_path(MYPLUG_MAIN_FILE));

// ... تعریف کلاس‌ها و توابع (بدون ثبت هوک) ...

require_once MYPLUG_PLUGIN_PATH . 'myplug-bootstrap.php';
```

<div dir="rtl">

و جای `TODO` در `myplug_boot()` با راه‌اندازی هستهٔ افزونه پر می‌شود (مثلاً `My_Plugin::get_instance();`).

### گام ۳: ممیزی

</div>

```bash
php ~/.claude/skills/rtl-license/scripts/check.php --plugin-dir=/path/to/plugin --prefix=myplug
```

<div dir="rtl">

هدف: **۰ FAIL**. هر WARN یا رفع می‌شود یا دلیل بی‌خطر بودنش توضیح داده می‌شود.

### گام ۴: بسته‌بندی

`templates/package.php` در `tools/package.php` افزونه کپی می‌شود و اجرا می‌شود:

</div>

```bash
php tools/package.php
php ~/.claude/skills/rtl-license/scripts/check.php --plugin-dir=. --prefix=myplug --pkg=dist/myplug
```

<div dir="rtl">

> فایل `<prefix>-bootstrap.php` را **راست‌چین پیش از انتشار با ionCube انکد می‌کند** تا گیت از نسخهٔ منتشرشده قابل حذف نباشد. به همین دلیل کل منطق گیت در همین یک فایل می‌ماند.

## معماری گیت لایسنس

</div>

```
plugins_loaded (priority 5)
        │
        ▼
  <prefix>_boot()
        │
        ├── <prefix>_license_active() ?
        │        │
        │        └── <prefix>_license_status()          ← فقط در static کش می‌شود
        │              1. smart_manager_active()?        → no-manager
        │              2. extension_loaded(ionCube)?     → no-loader
        │              3. sha1_file === LICENSE_HASH?     → no-license-file
        │              4. require + isActive() === true   → active | inactive
        │
        ├── ✔ active  → راه‌اندازی هستهٔ افزونه
        │              + admin_menu → زیرمنوی «مدیریت لایسنس» (اولویت ۹۹)
        │
        └── ✘ locked  → <prefix>_boot_locked()
                         • شورت‌کدهای ساکت (همهٔ تگ‌ها)
                         • لینک فعال‌سازی در ردیف افزونه
                         • اعلان پیشخوان، فقط اگر مدیریت هوشمند خاموش است
```

<div dir="rtl">

**تشخیص مدیریت هوشمند** با `class_exists('RtlRequired')` یا `RTL\RSM\Core\ServiceContainer` انجام می‌شود و در نبودِ آن، `RTL-CareUnit.php` در `active_plugins` (و `active_sitewide_plugins` در شبکه) جست‌وجو می‌شود. چون روی `plugins_loaded` اجرا می‌شود، به ترتیب بارگذاری افزونه‌ها و نام پوشه وابسته نیست.

**مقصد لینک فعال‌سازی:**
- مدیریت هوشمند نصب نیست ← صفحهٔ دانلود رسمی `https://www.rtl-theme.com/rtl-smart-management/` (زبانهٔ تازه)
- نصب است ← صفحهٔ خودش در پیشخوان (پیدا شده از منوی ثبت‌شده)؛ در نبودِ آن `plugins.php`

**متن مصوب اعلان پیشخوان** (نوع `notice-warning`):

> محصول **نام محصول** برای فعال‌سازی نیاز به افزونه **"مدیریت لایسنس راست‌چین"** دارد که در حال حاضر بر روی سایت شما نصب/فعال نشده است. جهت راهنمایی بیشتر به [این صفحه](https://www.rtl-theme.com/rcu-install-manual/) مراجعه نمایید.

## چک‌لیست‌ها

### ✅ چیزهایی که در حالت قفل نباید وجود داشته باشد

- [ ] منوی پیشخوان و صفحهٔ تنظیمات (`admin_menu`، `admin_init`)
- [ ] متاباکس و ذخیرهٔ متا (`add_meta_boxes`، `save_post`)
- [ ] فیلدهای ویرایش دسته‌بندی/ترم
- [ ] نمایش خودکار در محتوا یا آرشیو (`the_content`، `wp` و…)
- [ ] شورت‌کد فعال (فقط نسخهٔ ساکت مجاز است)
- [ ] بلوک گوتنبرگ (`register_block_type`)
- [ ] ویجت المنتور (`elementor/widgets/register`)
- [ ] نوع محتوا یا طبقه‌بندی سفارشی (`init` ← `register_post_type`)
- [ ] REST API (`rest_api_init`)
- [ ] `admin-post` / `admin-ajax` handlerها
- [ ] enqueue دارایی‌های فرانت و پیشخوان
- [ ] زیرمنوی «مدیریت لایسنس» (فقط در حالت فعال)

### ✅ چیزهایی که در حالت قفل *باید* وجود داشته باشد

- [ ] همهٔ تگ‌های شورت‌کد (جدید و قدیمی) ثبت شده‌اند و برای بازدیدکننده `''` برمی‌گردانند
- [ ] مدیر سایت به‌جای شورت‌کد یک خط دلیل قفل بودن می‌بیند، بدون نشت محتوا
- [ ] لینک «فعال‌سازی لایسنس» در ردیف افزونه، روی `plugin_action_links_` فایل اصلی
- [ ] اعلان پیشخوان **فقط** وقتی مدیریت هوشمند خاموش است، فقط برای `activate_plugins`

### ✅ بررسی‌های خودکار `check.php`

**۱) ساختار**
- [ ] دقیقاً یک فایل سطح ریشه هدر `Plugin Name:` دارد
- [ ] دقیقاً یک `RTL_License_*.php` در ریشه هست
- [ ] نام کلاس لایسنس در bootstrap با نام فایل یکی است
- [ ] sha1 فایل لایسنس با `<CONST>_LICENSE_HASH` می‌خواند
- [ ] فایل لایسنس انکدشدهٔ راست‌چین (ionCube) است
- [ ] bootstrap روی `plugins_loaded` می‌نشیند
- [ ] بررسی مدیریت هوشمند پیش از `isActive` است
- [ ] `extension_loaded('ionCube Loader')` پیش از `require` فایل لایسنس است
- [ ] `sha1_file` پیش از `require` است
- [ ] وضعیت لایسنس در transient یا option ذخیره نمی‌شود
- [ ] اعلان پیشخوان پشت `smart_manager_active()` است، نه رشتهٔ وضعیت کش‌شده
- [ ] زیرمنوی لایسنس بی‌قیدوشرط هوک نشده است
- [ ] bootstrap هدر افزونه ندارد
- [ ] فایل اصلی bootstrap را require می‌کند
- [ ] `<CONST>_MAIN_FILE` در فایل اصلی تعریف شده است
- [ ] جای `TODO` هستهٔ افزونه در بوت پر شده است

**۲) هوک‌های سطح فایل**
- [ ] هیچ `add_action` / `add_filter` / `add_shortcode` / `register_*` / `wp_enqueue_*` بیرون از تابع و کلاس نیست، مگر:
  - `plugins_loaded`، `register_activation_hook`، `register_deactivation_hook`، `register_uninstall_hook`
  - closureهایی که با `if (!<prefix>_license_active()) return;` شروع می‌شوند
  - فایل‌هایی که خود bootstrap آن‌ها را داخل شاخهٔ فعال require می‌کند

**۳) بوت واقعی در حالت قفل** (bootstrap با stubهای وردپرس، در دو سناریو)
- [ ] بدون مدیریت هوشمند: وضعیت `active` نیست و فقط `admin_notices`، `network_admin_notices` و `plugin_action_links_*` ثبت شده‌اند
- [ ] با مدیریت هوشمند و بدون لایسنس: وضعیت `active` نیست و **فقط** `plugin_action_links_*` ثبت شده است
- [ ] شورت‌کدهای ساکت ثبت شده‌اند

**۴) بستهٔ ساخته‌شده** (با `--pkg`)
- [ ] همهٔ بررسی‌های ساختار روی بسته
- [ ] `tests`، `tools`، `CLAUDE.md`، `.git` و `node_modules` در بسته نیستند

- [ ] همهٔ PHPهای بسته `php -l` را پاس می‌کنند
- [ ] hash فایل لایسنس در بسته با ثابت bootstrap می‌خواند
- [ ] دقیقاً یک فایل لایسنس در بسته هست

## ابزارها

| فایل | کاربرد |
|---|---|
| `SKILL.md` | دستورالعمل اسکیل برای Claude |
| `templates/license-bootstrap.php` | قالب گیت لایسنس با placeholderهای `__PREFIX__`، `__CONST__`، `__PRODUCT__`، `__TEXTDOMAIN__`، `__MENU_PARENT__`، `__SHORTCODES__`، `__LICENSE_CLASS__`، `__LICENSE_HASH__` |
| `scripts/scaffold.php` | ساخت bootstrap از قالب؛ نام کلاس و sha1 را از فایل لایسنس موجود می‌خواند |
| `scripts/check.php` | ممیزی خودکار (ساختار، هوک‌های سطح فایل، بوت حالت قفل، بسته) |
| `templates/package.php` | بسته‌ساز با سفیدفهرست و بررسی سلامت بسته |

### گزینه‌های `scaffold.php`

| گزینه | توضیح |
|---|---|
| `--plugin-dir` | ریشهٔ افزونه (محل `RTL_License_*.php`) |
| `--prefix` | پیشوند توابع با حروف کوچک؛ ثابت‌ها با حروف بزرگ همین ساخته می‌شوند |
| `--product` | نام فارسی محصول در اعلان‌ها |
| `--textdomain` | text domain افزونه |
| `--menu-parent` | اسلاگ منوی والد زیرمنوی «مدیریت لایسنس» |
| `--shortcodes` | همهٔ تگ‌های شورت‌کد، جداشده با ویرگول (اختیاری) |
| `--out` | نام فایل خروجی (پیش‌فرض: `<prefix>-bootstrap.php`) |
| `--force` | بازنویسی فایل موجود، مثلاً وقتی فایل لایسنس تازه‌ای گرفته‌اید |

### گزینه‌های `check.php`

| گزینه | توضیح |
|---|---|
| `--plugin-dir` | ریشهٔ افزونه |
| `--prefix` | پیشوند افزونه |
| `--bootstrap` | نام فایل bootstrap (پیش‌فرض: `<prefix>-bootstrap.php`) |
| `--pkg` | مسیر بستهٔ ساخته‌شده برای بررسی بخش ۴ |
| `--exclude` | پوشه‌هایی که ممیزی هوک نمی‌شوند، جداشده با ویرگول (مثلاً `demo,theme`) |

خروجی `check.php` با کد ۰ تمام می‌شود اگر FAIL نباشد، پس در CI هم قابل استفاده است.

## درس‌هایی که گران تمام شد

| اشتباه | پیامد | قاعدهٔ اسکیل |
|---|---|---|
| افزونه بدون مدیریت هوشمند هم کار می‌کرد | **رد در بازبینی** | کل هسته پشت گیت؛ ممیزی هوک‌های سطح فایل |
| کش وضعیت لایسنس در transient | خاموش کردن مدیریت هوشمند تا انقضای کش اثری نداشت | فقط `static` در همان درخواست |
| `require` فایل لایسنس بدون بررسی ionCube | «فتال ارور هنگام فعال‌سازی» روی هاست‌های بدون لودر | `extension_loaded` پیش از `require` |
| انتقال هدر افزونه به `index.php` | بازبین آن را محصول جدید دید؛ وردپرس افزونه را روی سایت‌ها غیرفعال کرد | فایل اصلی و پوشه هرگز عوض نمی‌شوند؛ shim برای ترمیم |
